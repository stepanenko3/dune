# Sandwalkers — бази, роадмап і мапа ресурсів для Dune: Awakening

Застосунок у стилі планувальника для Satisfactory, для будь-яких гравців і гільдій: розділи **Бази** (твої й
гільдійські; з давніх — **Sandwalkers Main**, 6 ділянок 10×10, і **Sandwalkers DD**, форпост у Глибокій пустелі),
**Роадмапи**, **Мапа**, **Бібліотека**, **Довідник**, **Калькулятор** і **Уміння**; облікові записи, гільдії й
панель керування.
Набір будівельних елементів — сардаукарський, з гранітного каменю. Використано **тільки квадратні й
трикутні плити**. Повороти на 30° зроблено так само, як у грі: квадрат → трикутник → повернутий квадрат.

## Запуск

Через Snotax console — сайт **https://dune.test** (`.snotax.yaml`: host-proxy, `npm run dev`, порт 5180):

```sh
npm install
snotax-console site link --yes      # один раз; далі консоль сама тримає dev-сервер
snotax-console env                  # .env з .env.example: з'єднання з Postgres і Mailpit
snotax-console db create dune       # база dune (і dune_testing — для тестів)
snotax-console worker reconcile     # якщо dev-сервер не піднявся одразу після link
```

**База** — Postgres зі Snotax console (`.env`: `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`;
`snotax-console env` пароль Postgres не вписує, якщо поруч стоїть і MySQL, — тоді вписати вручну). `.env` проєкту
головніший за оточення: Snotax підставляє dev-процесу свої загальні `DB_*`/`MAIL_*` (імена контейнерів, база
`laravel`), а сервер працює на самому Mac. Без `DB_HOST` — запасна SQLite у `server/data/app.db`. Коли Postgres
підключили вперше, сервер сам переносить туди все з `server/data/app.db` (раз; файл лишається як резервна копія).
**Пошта** (коди входу) — SMTP з `.env` (`MAIL_*`); у розробці це Mailpit, скринька —
http://127.0.0.1:8025/proxy/mailpit/. Без `MAIL_HOST` код пишеться в журнал сервера.

Без консолі: `npm run dev` → http://localhost:5180 (API на :5181, Vite проксує `/api`, `/map-tiles`, `/versions`).
Прод: `npm run build && npm start` → http://localhost:5181. Потрібен Node.js 22.5+. Тести (`npm test`) серверну
частину проганяють і на SQLite, і на Postgres `dune_testing` (якщо є `.env` і база відповідає).

**Демо-вміст** для бібліотеки — `npm run seed:demo` (`scripts/seed-demo.mjs`): три власні бази, зібрані з деталей гри
(будиночок 6×5, гараж-форпост для Глибокої пустелі, виробнича база на дві ділянки; бази гільдії лишаються
гільдійськими), п'ять білдів (коди — тим самим кодуванням, що й у планувальнику), два роадмапи, позначки на мапі й
записи ресурсів (точки — з даних мапи). Усе публічне, від імені першого адміністратора, власник — його гільдія;
створюється через звичайне API (перевірки, історія, журнал). Нікого не реєструє; вдруге без `-- --force` нічого не
робить, `-- --only bases` — лише один розділ (база з такою назвою вже є — пропускає). Інша база й сервер:
`ENV_FILE=… npm run seed:demo -- --api http://127.0.0.1:5191`.

## Головна

Глибока пустеля цього тижня: справжні тайли, сітка секторів і скан, що проявляє титан, стравідій і меланж
з найкращим сектором для кожного; нижче — 3D-орнітоптер (клік по двигунах — розкрутка, по прожектору —
скан), де найбільше руди за секторами, розділи і нещодавні записи «Наших ресурсів».
Моделі сцени — у `public/models/`: атрейдесівський орнітоптер «Atreides ornithopter Dune» (jorafe, CC BY 4.0;
`orni-atreides.glb` і легка `orni-atreides-lite.glb` для слабких пристроїв — `npm run orni:atreides -- "<тека зі
scene.gltf>"`, `npm run orni:lite`) і дрон «Buster Drone» (LaVADraGoN, CC BY 4.0; `buster-drone.glb` — `npm run
drone:buster -- "<тека>"`). Автори й ліцензії — підписом під сценою. Давня модель Харконненів — у `models-private/`
(чужа робота, не викладається й сайтом не віддається). Без файлу моделі блок сцени просто не показується.

## Довідник

Усі предмети, пристрої, рецепти й будівельні набори гри — як «Справочник» у Satisfactory: розділи,
підкатегорії й тіри, групування за типом (у техніки — за видом: піскоцикл, багі, орнітоптери…) або за тіром, пошук, картка з тим, як отримати (станція, час, інгредієнти), де використовується,
у яких будівельних наборах, і кнопка «Де випадає — на мапі» (підсвічує скрині з цим лутом).
Дані — questlog.gg (предмети, пристрої, рецепти, іконки), awakening.wiki (стоси, рідкість, будівельні
набори з цінами, CC BY-NC-SA), українські назви — з лут-описів TH.GL (списки з відсотками зіставляються
рядок у рядок, відсортовані за абеткою — розв'язуються викреслюванням; перевіряються «Mk N» ↔ «модель N»
і частина спорядження; перераховуються при кожному читанні каталогу). Збирається в
`server/data/catalog` (у git не йде): `npm run catalog:sync`, або сервер сам при першому відкритті.

## Події спільноти

Проєкт — `docs/superpowers/specs/2026-10-22-community-events-design.md` (там же — що ще можна зробити для спільноти).
Бій 2 на 2, турнір, перегони, PvE-вилазка, ярмарок, збір гільдії — у визначений час (`/events`: «Найближчі · Мої ·
Гільдія · Минулі», фільтр за видом і регіоном; подія — `/events/<id>`, нова — `/events/new`, редагування —
`/events/<id>/edit`). Подія — річ реєстру (`kind: 'event'`): власник, видимість, права, ліміти, панель і історія змін —
як у всіх речей. Час — мить UTC: кожен бачить свій, поруч — час серверів регіону гри. Дві точки на мапі гри — місце
події й зона для глядачів (`/map?m=…&at=x,y` підлітає до точки). Призовий фонд, внесок, правила, трансляція.
Реєстрація: формат «N на N» чи кожен сам за себе, місця (далі — резерв, звільнилось — перший із резерву проходить сам),
підтвердження організатором; команду реєструє капітан (ніки в грі), согравці з сайту приєднуються посиланням-кодом
(нік на сайті не збігся з вписаними капітаном — людина вибирає, хто з них вона); людина — лише в одній команді події. «Піду дивитись», сітка турніру на вибування (`src/engine/bracket.mjs` — та сама
в браузері й на сервері), результати з призами, скасування з причиною, «Створити схожу», календар `.ics` (нагадування
за 30 хв), Google Календар, текст для Discord (`<t:…:F>`), прев'ю посилання. Живі оновлення — `/api/events/stream`.
Сервер — `server/lib/events.mjs`, `server/routes/events.mjs`; клієнт — `src/pages/Events.tsx`, `EventPage.tsx`,
`EventEditor.tsx`, `src/components/events/`, `src/lib/events.ts`; тести — `server/events.test.mjs`,
`src/engine/bracket.test.ts`. Знімки сторінок — `docs/superpowers/screens/2026-10-22-events/`.

## Таймер бурі Коріоліса

На головній (біля «Цей тиждень у Глибокій пустелі») і на мапі Глибокої пустелі — відлік до щотижневого
скидання DD (`src/lib/ddReset.ts`, `src/components/DDTimer.tsx`; той самий розклад на сервері — `server/lib/storm.mjs`,
для нагадувань і перевірки TH.GL). Буря — у вівторок о 05:00 за місцевим часом регіону, з переходом на літній і
зимовий час (Європа — Europe/Berlin, Північна Америка — America/Chicago, Південна — America/Sao_Paulo, Океанія —
Australia/Sydney; вибір зберігається в браузері; година — з фанатських трекерів, офіційно не підтверджена, тому
поруч — «звірятися з Communinet»). За 6 год — попередження, як Communinet у грі. На мапі Глибокої пустелі рядок
«Розкладка N · буря через …» розгортається в розкладки, таймер і регіон картками. Якщо мапа ще з
минулого тижня — підказка, що TH.GL не оновив розкладку; у вікно після бурі сервер перевіряє TH.GL
кожні 30 хв замість 6 год. Окрема картка на головній; коли до бурі менше доби — смуга під шапкою на всіх
сторінках (можна сховати до наступної бурі). Нагадування — Web Push за добу або 12 год (`server/lib/push.mjs`,
`public/sw.js`): приходять і з закритим сайтом, поки браузер запущений; ключі VAPID — `server/data/push-vapid.json`.

## Адреси вкладок

Кожна вкладка й фільтр-вкладка — своє посилання (`src/lib/urlState.ts`, `useUrlParam`; у `Seg` — `href`): розділ гільдії
(`/g/<адреса>?tab=items`), фільтр гільдій (`?show=open`), бібліотека (`?kind=base&sort=stars`), довідник (`/catalog/<розділ>`,
`?g=<група>&tier=4`), школа вмінь (`/skills?s=mentat`, поруч із кодом білду `b`), план чи 3D бази (`?view=3d`), мапа
(`/map?m=…`), вкладки картки в панелі (`?tab=members`) і переклади в панелі (`?lang=de&show=all`). Звичайний клік
перемикає без перезавантаження, з Ctrl/⌘ — відкриває в новій вкладці; «назад» повертає попередню.

## Облікові записи, гільдії, доступ, бібліотека

Проєкт — `docs/superpowers/specs/2026-10-19-accounts-guilds-library-design.md`.

- **Вхід і реєстрація** — одне й те саме: пошта → 6-значний код у листі (діє 10 хв, 5 спроб, новий — раз на 45 с) →
  вхід; нова пошта — новий обліковий запис. Паролів нема. Ім'я й адреса сторінки (`/u/<логін>`) — з пошти, змінити
  можна в профілі. Сеанс — cookie `sw_session` (HttpOnly, SameSite=Lax), у базі лише хеші сеансів і кодів, 30 днів із
  подовженням. Зміни приймаються лише з самого сайту (Sec-Fetch-Site / Origin), спроби обмежено. **Перший, хто увійде,
  — адміністратор сайту й лідер гільдії Sandwalkers**, якій перейшло все, що було до облікових записів.
- **Профіль** (`/me`): ім'я, адреса сторінки, нік у грі, про себе, колір, основна гільдія, сеанси, видалення себе.
  Сторінка людини — `/u/<логін>` (її публічне).
- **Гільдії** (`/guilds` — усі гільдії з пошуком і «Подати заявку», `/g/<адреса>`): ролі лідер → офіцер → учасник →
  новобранець; вступ за запрошенням-посиланням (`/invite/<код>`, термін і кількість використань) чи заявкою (якщо
  гільдія приймає заявки; прийнятий — новобранець). Як у грі, **гільдія в людини одна** (щоб вступити в іншу чи
  створити свою, спершу вийти), і в гільдії є **ліміт учасників** — 32, змінюється в панелі («Налаштування сайту»);
  повна гільдія нових не приймає. З профілю й меню акаунта — перехід у свою гільдію.
- **Власник і видимість** — у кожної бази, роадмапу, білду, позначки на мапі й запису ресурсу (реєстр речей,
  `server/lib/items.mjs`): «Особисте» (лише людина), «Гільдія» (учасники), «За посиланням», «Публічне» (бібліотека).
  Значок доступу — на кожній картці й сторінці; «Доступ» — передати собі чи гільдії й змінити видимість. Права в
  гільдії: новобранець дивиться, учасник змінює, офіцер ще й видаляє й міняє доступ. Живі оновлення (SSE) йдуть лише
  тим, хто річ бачить.
- **Бібліотека** (`/library`): публічні бази, білди, роадмапи й розрахунки калькулятора — вид (вкладки зліва), пошук,
  «Нові / Популярні / Копіюють», зірки, «Копіювати собі» (копія — особиста, з позначкою «на основі …»); виділене
  модераторами — згори.
- **Офіційне від сайту** — власник «Сайт» (ставить лише адміністрація): такі речі не з'являються в чиїхось списках
  («Мої», гільдія), лише в бібліотеці, з назвою сайту як автором. Так належить демо-вміст (`npm run seed:demo`).
- **Ліміти**: скільки баз, роадмапів, білдів, розрахунків, позначок і записів ресурсів може мати одна людина й одна
  гільдія (бази в кошику теж рахуються) — «Налаштування сайту» → «Ліміти» (0 — без обмежень; адміністрацію й
  офіційне від сайту не стосуються). Перевірка — одна на всі шляхи появи речі: створення, імпорт, копія, передача.
- **Розрахунки калькулятора** зберігаються так само, як білди: меню «Зберегти й поділитись» (зберегти, мої розрахунки,
  посилання, бібліотека); `/calculator?calc=<id>` відкриває збережений. Сторінка калькулятора завжди починає з першого кроку.
- **Панель керування** (`/admin`) — див. розділ нижче.
- **Білди умінь** — зберігаються з планувальника (`/skills`: меню «Дії» — зберегти, мої білди, посилання, бібліотека
  білдів, скинути; `/skills?build=<id>`).
  **Позначки на мапі** — база, аванпост, ресурс, небезпека, збір, нотатка (панель мапи → «Позначки»).

Сервер: `server/lib/sql.mjs` (Postgres чи SQLite, один асинхронний інтерфейс), `import-sqlite.mjs` (перенесення),
`mail.mjs` (листи), `auth.mjs` (люди, сеанси, коди входу, журнал, налаштування), `guilds.mjs`, `items.mjs` (реєстр, права,
бібліотека, SSE з доступом), `content.mjs` (створити, скопіювати, стерти, передати будь-яку річ), `docs.mjs` (білди й
позначки), `roadmap.mjs` (багато роадмапів), `decree.mjs`; маршрути — `server/routes/{auth,guilds,items,admin,docs}.mjs`.
Тести — `server/app.test.mjs` (справжній HTTP на тимчасовій базі).

## Панель керування

`/admin` — як Filament, але під сайт: бічне меню з усіма розділами, огляд (люди, гільдії, вміст, оголошення, дані гри,
готовність перекладів, реєстрації за 30 днів, останні дії), і для кожної таблиці — список із пошуком, фільтрами,
сортуванням, вибором стовпців і сторінками, вибір рядків із масовими діями, картка запису (створити, змінити,
видалити, дії, «На сайті»). Розділи: **Люди** (люди, сеанси, коди входу), **Гільдії** (гільдії, учасники,
запрошення, заявки), **Вміст** (реєстр речей, бази, роадмапи, білди, позначки, записи ресурсів, версії, зірки — документи
редагуються як JSON і проходять ту саму перевірку, що й з редактора), **Гра** (предмети, пристрої, рецепти, будівельні
елементи, уміння, тексти гри мовами), **Сайт** (оголошення, переклади сайту, налаштування, журнал дій, сповіщення про
бурю, історія змін, фонові задачі, запуски задач, службові позначки).

- **Ролі й права** — таблиця `roles` (`server/lib/roles.mjs`): у ролі — дозволи на кожен розділ панелі
  (`<розділ>.view|create|edit|delete|<дія>`) і на сайт (`admin` — вхід у панель, `site.moderate`, `site.settings`,
  `site.decree`); у картці ролі — галочками, кожна група розділів окремим блоком. Вбудовані: «Адміністратор» (усе,
  `*`, не змінюється), «Модератор» (бачить людей, вміст, гру, журнал і задачі, блокує, модерує бібліотеку, веде
  оголошення), «Користувач» (без панелі). Свої ролі створюються в панелі («Дублювати» — копія з тими самими правами);
  роль, яку хтось має, не видалити. Нові дозволи вбудованих ролей із коду (новий розділ) додаються самі, а прибране
  адміністратором не повертається (`roles.seeded`).
- **Хто кого може змінювати**: адміністрацію (тих, хто має вхід у панель) — лише той, хто має всі права; решту — якщо
  роль людини не ширша за власні права; дати роль — лише якщо маєш усі її права; пошту (це вхід!) — лише адміністратор
  (старі сеанси й коди тоді закриваються); собі — ні роль, ні блокування, ні видалення; останнього адміністратора не
  прибрати. Роль із правом змінювати ролі дає лише ті права, які має сама, і свою роль не змінює.
- **Історія змін** — кожна зміна будь-якого запису (з сайту й з панелі, і налаштувань сайту): хто, коли, що було й
  що стало (`server/lib/revisions.mjs`; різниця — за полями з їхніми підписами, у документах баз — за id деталей). Одна
  зміна — одна версія (сховища, які кличе панель, своєї не пишуть); документи баз і роадмапів у версії не копіюються
  (у них своя історія). Видно лише зміни розділів, які людина сама бачить. У картці запису — вкладка «Історія змін»
  (сторінками по 50), для версій баз і роадмапів — «Що змінилось у наступній версії».
- **Журнал дій** — кожен запит, що щось змінює (`server/lib/audit.mjs`): хто, коли, результат, тривалість, IP; коди
  входу й токени сховано. Людською мовою його показує `server/admin/describe.mjs` («PUT /api/bases/:id» → «Збереження
  бази» і назва бази з посиланням) — **новий маршрут, що щось змінює, варто додати туди**. Журнал та історію не
  видалити з панелі; старіше за N днів («Налаштування сайту» → «Журнал і історія») прибирає задача «Прибирання».
- **Пов'язані записи** (як relation managers): у картці гільдії — її учасники, речі, запрошення, заявки; у людини — її
  гільдія, речі, сеанси, зірки, журнал; у бази — версії й сама база (той самий перегляд плану й 3D і той самий
  редактор, що на сайті); у ролі — люди з нею. Вкладки-«пігулки» над таблицею; «Створити» в їхньому рядку відкриває
  форму з уже заданим зв'язком. Поля-зв'язки у формі (власник, людина, гільдія) — з пошуком на сервері; у «Фільтрах»
  таблиці — текстом (ім'я, пошта, назва), без завантаження всього списку.
- **Вигляд**: сторінка прокручується вся, меню розділів — плаваючий блок, що стоїть на місці; над заголовком — крихти
  (на телефоні поруч — кнопка меню).
- **Таблиці**: стан (пошук, фільтри, сортування, сторінка, швидкі фільтри) — в адресі (`?t_qf=banned`), тож «Назад» і
  посилання його зберігають; швидкі фільтри над таблицею (`quick` у описі розділу: «Заблоковані», «Сховане», «З
  помилкою»…); сховані стовпці браузер пам'ятає; «CSV» — увесь відфільтрований список файлом (до 10 000 рядків); зв'язки
  в комірках і на картці — посилання на запис.
- **Пошук у панелі** — Ctrl/⌘+K: розділи за назвою й записи всіх розділів, які людина бачить (`/api/admin/search`).
- **Картка запису**: незбережені зміни — перехід і закриття вкладки питають; Ctrl/⌘+S — зберегти; помилка біля поля;
  хибний JSON не зберегти; хтось змінив запис, поки його правили, — 409 (картка шле `_updated`). Після «Створити» з
  вкладки картки — назад на ту саму картку.
- **Огляд**: «Потребує уваги» (заявки, задачі з помилкою, заблоковані — одразу у відфільтрований список), останні дії
  людською мовою; новенькі й задачі — лише тим, хто бачить ці розділи.
- **Фонові задачі** (`server/lib/cron.mjs`): оновлення мапи (кожні 5 хв), знімки баз, збір довідника й умінь (щосереди),
  назви TH.GL, прибирання сеансів, кодів, старого журналу й історії — за розкладом як у cron (час сервера); у панелі —
  розклад (змінюється; той, що ніколи не спрацює, не приймається), наступний і останній запуск, кількість запусків і
  помилок, журнал кожного запуску, «Запустити зараз» (у фоні — хід видно в «Запусках задач»; збір довідника з розділів
  гри — той самий запуск). Запуски, обірвані перезапуском сервера, позначаються помилкою.
- **Бази** — «Імпортувати з файлу» і «Вивантажити» (та сама перевірка, що й на сайті: помилки з місцем у файлі).

Рушій — `server/admin/engine.mjs` (опис ресурсу → SQL для обох баз, права, дії, журнал), розділи —
`server/admin/resources.mjs`, маршрути — `server/routes/admin.mjs`; клієнт — `src/pages/admin/` (таблиці й форми будуються
з опису, що віддає `/api/admin/meta`).

**Оголошення** — смужка вгорі сайту з датами показу («Початок» / «Кінець»), тоном, аудиторією (усім, гостям, тим, хто
увійшов, учасникам гільдії, адміністрації), мовою й посиланням. Масово — серією (те саме щодня / щотижня / щомісяця N
разів) чи списком; пакет потім разом зсувається, вимикається чи видаляється.

## Мови

Сайт — усіма 14 мовами гри (українська, англійська, німецька, французька, іспанська, італійська, польська, бразильська
португальська, російська, турецька, японська, корейська, китайська спрощена й традиційна). Вибір — у шапці й у профілі
(зберігається в профілі); без вибору — мова браузера, далі — мова за замовчуванням із налаштувань сайту.

- **Інтерфейс** — як gettext: у коді український текст, `t('Бази')`, `t('через {n} с', { n })`, `<T text="…{x}…" x={…}/>`
  (`src/lib/i18n.tsx`); на сервері — `req.t()` і `fail('текст {x}', код, { x })` (`server/lib/i18n.mjs`), мова — з
  cookie `sw_lang`. Переклади — `locales/<мова>.json`, правки з панелі («Переклади сайту») важливіші за файли.
  `npm run i18n:extract` збирає всі тексти з коду в `locales/keys.json` і показує, скільки бракує кожною мовою;
  `npm run i18n:merge` зливає частини перекладів із `locales/parts/`.
- **Дані гри** (назви й описи предметів, пристроїв, рецептів, будівельних елементів, умінь) — з dune.gaming.tools: там
  вони витягнуті з файлів гри всіма 14 мовами. Сервер туди не пускає Cloudflare, тож імпорт — кнопкою в панелі
  («Тексти гри мовами» → «Імпорт з gaming.tools»): файли тягне браузер адміністратора, на сервер іде готове.
  Українські назви ще й зі словників мапи TH.GL; описи — ще й із questlog (8 мов). Назви на мапі — зі словників TH.GL
  мовою сайту.

## Дані гри в базі

Довідник, калькулятор і планувальник умінь читають таблиці `game_items`, `game_placeables`, `game_recipes`,
`game_buildables`, `game_skills` і `game_texts` (тексти мовами; `server/lib/gamedata.mjs`). Збір із questlog/вікі
(`npm run catalog:sync` чи кнопка в панелі) пише туди ж; запис, змінений у панелі, — закріплений, збір його не чіпає;
прихований — сайт не показує. Уперше таблиці заповнюються з давніх `server/data/catalog/catalog.json` і
`server/data/skills/skills.json`.

## Компоненти

Інтерфейс — на `@snotax/ui` (веб-компоненти Lit `sn-*`): кнопки, поля, вікна, таблиці, бічне меню панелі, поле коду
входу (`sn-input-otp`). Бібліотека — зібраний `dist` у `vendor/snotax-ui` (`npm run ui:sync` з робочої копії Snotax; з

обгортки для React — `src/components/sn` (важкі компоненти панелі — таблиця, бічне меню, календар — у `admin.ts`, окремим
шматком збірки). Токени (`--background`, `--primary`…) — з нашої
пісочної палітри (`src/index.css`), темна тема — `.sn-theme-dark` разом із `.dark`.

## Указ Ландсрааду

У грі указ один на весь сервер (його обирає фракція-переможець Ландсрааду), тож і на сайті він один: виставляє
адміністрація в панелі («Налаштування сайту», дозвіл `site.decree`), головна лише показує, калькулятор враховує
(`/api/decree`; зберігається в налаштуваннях сайту). Автоматично взяти нема звідки — гра й вікі поточний указ назовні
не віддають. Діє до найближчої бурі й скидається сам. Список із 10 відомих указів — `src/lib/decree.ts` (за awakening.wiki/Landsraad).

## Калькулятор виробництва

Один компонент (`src/components/catalog/ProdCalc.tsx`, розрахунок — `src/lib/calc.ts`) у чотирьох місцях —
сторінка кожної бази (ціль — деталі й пристрої бази, `src/components/base/BaseCalc.tsx`; числа, змінені тими, хто
може змінювати базу, — спільні для всіх, решта міняє їх лише в себе), сторінка **Калькулятор** (`/calculator`, свій
список предметів і будівель; список — в адресі `?t=`, ним можна поділитися; розрахунок можна зберегти — `?calc=`, з
указом, доступом і бібліотекою), картка предмета довідника (кількість) і картка будівлі чи пристрою (вартість ×
кількість будівель). Кроки — вкладками зі своєю адресою (`?step=goal|stations|need|gather|trips|process`): що
треба, станції, скільки всього, що видобути (сировина) і що брати як лут чи в торговця, ходки транспортом (`?haul=`)
і переробка. Рецепти — по всьому дереву (де їх кілька — вибір, за замовчуванням найощадливіший); побічні продукти
рахуються раз на крафт і показуються («а ще: …», «Побічно лишиться: …»); знижка Глибокої пустелі й вода з указом
округлюються вгору. Енергобаланс бази — з потужностей пристроїв довідника (`src/components/base/power.ts`).
Збережений розрахунок після оновлення гри показує окремо цілі й рецепти, яких уже нема.

Указ тижня — лише той, що вибрано на головній, і скрізь однаково (`decreeFx`): у калькуляторі видно, що
враховано, а в рецептах довідника кількості з указом, стара — закреслена. «Виробничий контракт CHOAM» — −25%
входів і води за крафт від тіру 4 (вгору, як у грі), «Контракт на переробку» — −75% часу на переробниках.
Вартість самої будівлі указ не знижує — лише крафт її матеріалів.

## Таймер відновлення вузлів

На мапі позначка «зібрано» на вузлі руди чи місці збору запам'ятовує час: на іконці — дуга відновлення,
у бічній панелі — скільки вузлів відновлюється і коли найближчий; мине час (45 хв за замовчуванням, можна
змінити) — позначка знімається сама. Поля меланжу не відновлюються — у них звичайна галочка.

## Роадмап

Роадмапів багато — у кожного власник і видимість (`/roadmap` — мої й гільдійські, `/roadmap/<id>` — роадмап; стара
адреса `/plan` перенаправляє): назва, вступ і ключові цифри,
блок «Зараз є», етапи — статус (заплановано / у роботі / готово), позначка, опис, таблиця вартості з
довільними стовпцями й рядками-підсумками, чекліст задач, примітка — і розділи з цифрами, колонками й
джерелами. Усе редагується в застосунку («Редагувати»); статус етапу й галочки задач — і без режиму
редагування. Тексти — у мінімальній розмітці: `**жирний**`, `[посилання](адреса)`, рядки `- ` і `1. `.

Зберігається в базі сайту (Postgres, запасна — SQLite; `server/lib/roadmap.mjs`, таблиці `roadmaps` і `roadmap_history`), автоматично за ~0,7 с
після правки. Кожне збереження несе версію, від якої редагували: якщо хтось устиг раніше — 409 і свіжа
версія, щоб не затерти чужі зміни. Останні 100 версій — в «Історії», з відновленням; «Скасувати» — у
межах вкладки. Інші вкладки оновлюються через SSE (`/api/roadmaps/stream`). Змінювати можуть ті, кому дозволено
(власник; у гільдії — учасники), решта бачить лише перегляд. Початковий вміст — `data/roadmap.json`.

## Мапа

Як «Карта» в Satisfactory, але для Арракіса: тайли гри і **всі точки з гри** — локації, печери, уламки,
випробувальні станції, торговці, тренери, NPC, скрині й лут, руда, рослини, підбирання, ключі
пентащитів, представники Домів. Фільтр за групами й типами, пошук місць, наведення і клік по точці
(назва, що лежить у скрині й з яким шансом, координати), позначки «зібрано». Наведення на локацію
показує, як у грі, **що там є**: лут контейнерів поблизу з відсотками і руду / рослини довкола.
Однакові значки при віддаленні **групуються з лічильником** (кнопка праворуч вмикає й вимикає це):
у Глибокій пустелі одразу видно, біля якої скелі титану найбільше, — наведення показує тип, кількість
і сектор, клік наближає групу. Зум плавний (колесо й тачпад), значки й підкладка не зникають під час масштабування, за край мапи
не тягнеться. Поля меланжу — свої позначки трьох розмірів: мале (жовте), середнє (помаранчеве, «С»),
велике (червоне, «В»).

- **Мапи:** Хагга, Глибока пустеля, Арракін, Харко, а також уламки, печери й підземелля — усі вкладками.
  «Карту поверхні» з TH.GL не показуємо: її тайли там порожні.
- **Сітка секторів Глибокої пустелі** A1…I9 (ряд A знизу, біля Щитової стіни; стовпці 1…9 зліва),
  сектор видно в координатах під курсором і в картці точки. Сітка накладена на межі мапи TH.GL —
  постійні випробувальні станції №37, 93, 148, 185, 186, 217 лягають у ряд A.
- **Глибока пустеля — окрема мапа, яку буря перебудовує щотижня.** TH.GL тримає всі 12 розкладок
  (тайли й точки кожної) з позначкою поточної. Сервер сам перевіряє раз на 6 годин, яка зараз у грі,
  і веде історію тижнів; на мапі можна перемкнути тиждень. Наші точки в DD прив'язуються до свого тижня
  і на чужому показуються лише контуром — після бурі там інакше.
- **Наші ресурси** — шар поверх даних гри: де брати унікальні ресурси (те, що раніше було вкладкою
  «Ресурси»). Запис прив'язується трьома способами, і мапа показує все разом:
  - **точки** — ромби кольору спайсу (клік «Вказати на мапі» або «+ до запису» з картки точки);
  - **типи точок** — кільця навколо всіх печер, уламків, випробувальних станцій тощо;
  - **предмет луту** — усі контейнери, у луті яких він є, з відсотком випадіння і списком найкращих.
  Записи спільні (у базі на сервері), зміни розлітаються по відкритих вкладках; «перевірено в грі» — галочкою.
  **Галочки біля записів — фільтр** (і вибраний запис теж): мапа лишає тільки місця, де є ці ресурси (контейнери з лутом,
  локації, де вони лежать, пов'язані типи, наші точки). Запис може бути й просто своєю точкою
  («Важка броня — випробувальна станція №13»): у картці будь-якої точки є «Наш ресурс тут» і «+ до запису».
- **Панель мапи — дві сторінки** (`?side=game|marks`): «Гра» — шари ігрових точок (група «Підбирання з землі» за
  замовчуванням вимкнена), «Позначки» — усе від гравців: позначки й записи ресурсів одним списком, вкладки «Мої /
  Гільдія / Публічні», пошук. На мапі за замовчуванням лише свої й гільдійські; чуже публічне — списком сторінками
  (`/api/map/public`) і вмикається поштучно чи «усе від автора» (запам'ятовується).
- Дані мапи — [TH.GL](https://duneawakening.th.gl): сервер тягне їх з CDN і кешує на диск
  (`server/data/map`, у git не йде). `npm run map:prefetch` завантажує все наперед для роботи без мережі,
  `npm run map:sync` оновлює знімок опису мап у репозиторії (`server/map/source.json`).

## Бази: редактор, вивантаження й імпорт

База — документ із деталей гри (format 2: фундаменти, стіни, дахи… і станції), з якого рахуються план, 3D, ліміти й
калькулятор. Редактор — `/bases/<id>/edit`, як будування в грі: меню будівлі з деталями й окремою секцією
**«Станції»** (переробники, фабрикатори, сховища, енергія, техніка), примара під курсором, R — поворот. Вибране
(деталь, групу чи станцію) можна **тягнути мишею** або рухати **стрілками** (← → — уліво-вправо, ↑ ↓ — від себе й до
себе, як дивиться камера; Shift — на 0,1 для станцій); на зайняте місце не стане, серія натискань — один крок Ctrl+Z.

**Видалена база** — у кошику: на сторінках гільдії й у списку баз вона сіра, з «Повернути» й «Видалити назавжди»
(стирає базу з усіма версіями — лише з кошика й лише тим, хто нею керує); у бібліотеці її не видно.

**Вивантажити** (сторінка бази) — файл JSON (`sandwalkers-base/1`: назва, версія, звідки, сам документ).
**Імпортувати** (сторінка «Бази» чи панель керування) — спершу перевірка (`validateBase`, `server/lib/bases.mjs`):
помилки з місцем у файлі (`doc.pieces[12].shape: невідома деталь`), попередження (дрібне виправиться саме) і підсумок;
з помилками нічого не створюється. Приймається файл вивантаження, відповідь API або сам документ (і давній формат).

## Sandwalkers Main

![3D, тил](renders/3d-back.png)

Ділянки стоять сіткою **2 × 3** (20 плит завширшки, 30 углиб).

- **Перед.** Центральний заїзд 3 + 2 плити, заокруглений знизу і зверху (скрін 3), заїзди в гаражі 2 плити на рівні підлоги.
  - Гараж краулера: дах зі скошеним карнизом і пентащитом 4×9 з відступом від країв.
  - Гараж багі: дах-тераса з вітропастками.
  - Над заїздом перехід зі скошеним дахом, посередині виріз із круглим балконом.
- **Центр.** Великий зал — витягнутий шестикутник: спереду квадрати 11×5, ззаду трикутна фаска. Унизу фабрикатори (виживання, зброї, одягу), ресайклер і склад деталей; галерея на +5.
  - Впритул обабіч — прямі двоповерхові блоки (спільна стіна із залом): внизу головний склад (лівий, контейнери обабіч проходу) і цех меланжу (правий, 2 великі переробники спайсу), нагорі водний блок і майстерня техніки.
  - Вежі починаються з +9 і стоять на дахах блоків; сходи в них — з другого поверху блоку через люк. Балкони з трьох боків, місток між вежами на +15 над переходом, як брама.
- **Тил.** За Великим залом задній зал — перевернутий шестикутник.
  - Перший поверх — рудний цех (3 великі переробники руди + середній) обабіч проходу до заднього входу; склад перенесено в лівий блок, бо в трикутному залі контейнери 1×1 не лягають рівно. Обабіч одноповерхові крила між тилом блоків, фаскою залу і заднім залом (зовнішня стіна навскіс): генераторна і хімічна. Над їхніми ромбами біля залу на +5 — прибудови.
  - Задній вхід заглиблено на 2 ряди: портал урівень із задньою стороною, двері глибше, над ними навіс галереї і круглий балкон.
  - До скошених граней на +5 під кутом кріпляться ангари орні (скрін): зліва асаултів — 6 плит на всю грань (один асаулт), справа скаутів — 5 плит, зсунутий на плиту до центру. Вони звисають над обривом: під ними порожньо, знизу днище і консолі. Пентащита зверху немає.
- **Ангар грузових** на 2 місця поруч стоїть на дахах Великого залу, заднього залу і прибудов: окремої підлоги немає, кожна стіна стоїть над стіною нижче (інакше в грі бракує стабільності), грані йдуть лише по ребрах плит. Спереду 11 плит і портал під містком, посередині розширення до 14 над прибудовами, ззаду портал 9 плит на задній майданчик — над ангарами орні не нависає. Вхід лише другим маршем парадних сходів по центру залу: з галереї +5 біля переходу нагору, вихід між грузовими. Трикутний дах тримає одна колона по центру біля заднього порталу. На даху ступінчаста гора (скрін 4), за нею 20 вітряків.
- **Фасади.** Кожен корпус має свій відтінок стін, ребра на кутах і стиках, пояси і карнизи.

### Рівні

| Рівень | Що там |
|---|---|
| 0 | Заїзд, гаражі, Великий зал із фабрикаторами, головний склад (лівий блок), цех меланжу (правий), рудний цех із крилами в задньому залі, заглиблений задній вхід. Під ангарами орні — обрив |
| +5 | Перехід із круглим балконом, дах гаража багі, галерея залу, водний блок, майстерня, задня галерея, прибудови над крилами, ангари орні над обривом (пентащит до +8, дах +8 і +9), задній балкон |
| +9 | Ангар грузових, задній майданчик, вежі (від даху блоків), дахи бічних блоків із вітропастками, дахи ангарів |
| +13 | Дах ангара грузових: гора до +16, 20 вітряків; балкони веж і місток +15, ліхтарі +17…+19,5 |

![План, рівень +5](renders/plan-u.png)

### Фундамент

Рівень 0 — один суцільний фундамент без жодної щілини. Квадрати і трикутники без залишку стикуються лише по горизонтальній лінії, тому квадратна частина (заїзд, гаражі, цехи, перед залу) і трикутна (фаска залу, задній зал, крила складу) межують тільки по горизонталі: по y = 17. `tools/check-model.js` перевіряє, що плитки лягають край у край і всередині немає дірок. У 3D режим «Тільки плити підлоги» показує самі плити вибраного поверху.

### План будівництва і калькулятор бази

Унизу сторінки — етапи будівництва з кількістю деталей на кожному (фундамент → стіни 1-го поверху → перекриття +5 → 2-й поверх → ангари орні → дахи +9 і ангар грузових → вежі, гора, місток → пристрої) і калькулятор бази замість кошторису: ціль — будівлі бази з моделі (деталі в гранітному камені, пентащити й пристрої за рецептами з гри — поле `recipe` в моделі, таблиця `RECIPES` у `src/build.js`, паливо генераторів на тиждень), у DD — зі знижкою. Кількість можна змінити, рядки прибрати, додати інше з довідника (правки — для кожної бази окремо, «Скинути до моделі бази» повертає модель); далі калькулятор рахує, що потрібно на будівництво, сировину, крафти, де і скільки часу, воду, з указом тижня; там само — енергобаланс. Цілі — усі деталі й пристрої моделі: пристрої з полем `recipe` — за рецептами моделі, решта — за будівельними записами довідника (таблиця `PLACE` у `src/components/base/BaseCalc.tsx`; де ціни немає — лише для лімітів). Картка «Будівельні елементи» (ліміт 5 000, групи деталей і всі інші ліміти бази) стоїть одразу перед калькулятором і рахується повністю з його цілей (`useBaseTargets`), тож будь-яка правка в калькуляторі одразу видно в лімітах. Підрахунок — `src/build.js`. На плані є опція «Координати» (стовпці A–T, ряди 1–30 від фронту).

### Як ходити базою

- **Земля.** Вулиця → заїзд → гаражі → цехи → Великий зал → головний склад і крила → задній вхід.
- **З землі на +5.** Парадні сходи Великого залу, сходи в обох цехах.
- **+5.** Перехід ↔ водний блок і майстерня ↔ галерея Великого залу ↔ задня галерея ↔ ангари орні ↔ задній балкон.
- **+9.** Ангар грузових: сходи із задньої галереї через люк на задній майданчик, або з переходу — вихід перед переднім порталом. Вежі: з водного блоку і майстерні через люк.
- **+15.** Вежі → балкони → місток. Вузькі сходи між грузовими → дах із вітряками.

### Пристрої на дахах

- **20 вітряків** (1×1): чотири стовпці по 5 за горою на даху ангара грузових (+13).
- **15 вітропасток** (1,5×1,5): 7 у глибині даху гаража багі (+5), по 4 на дахах бічних блоків (+9).
- Біля ангарів орні пристроїв немає.

## Розміри

- Грузовий 4×9, великий рудний переробник 3×2 заввишки до 2 — з уточнень.
- Великий переробник спайсу 3×2, 5 стін; цех меланжу має рівно 5 рівнів — впритул. Контейнер складу 1×1, 2 стіни заввишки.
- Скаут ≈ 3,6×2,5, асаулт ≈ 4×2,7; ангари 3 рівні скла + верхній ярус даху.
- Краулер ≈ 5,5×2,6, багі 3×2, піскоцикл 2×1.
- Вітряк займає 1×1, вітропастка 1,5×1,5. Над ними нічого немає.

**Перевірити в грі:** чи проходить краулер у заїзд шириною 2 плити, чи проходить грузовий крізь горизонтальний пентащит, чи вистачає 4 рівнів ангара грузових і чи влазить переробник спайсу під стелю на 5 стін.

## Робочий сайт

- **Змінні середовища**: `APP_URL` (адреса сайту — для посилань у листах і прев'ю), `MAIL_*` (без `MAIL_HOST` код входу
  лише в журналі — сервер попереджає на старті), `HOST` (адреса прослуховування, за замовчуванням `127.0.0.1`),
  `PORT`. `.env` проєкту головніший за оточення (див. «Запуск»).
- **Зупинка** (`SIGTERM`/`SIGINT`): нових з'єднань не бере, початі запити дописує, закриває базу; живі потоки — до 10 с.
  Необроблені відмови — у журнал, а не падіння. `/api/health` перевіряє й базу (503, коли вона недоступна).
- **Сторінки**: невідома адреса — сторінка «Такої сторінки нема» з кодом 404; файли збірки `/assets` кешуються на рік,
  а відсутній шматок старої збірки — 404, і вкладка після оновлення сайту сама перезавантажується (раз), а не
  показує білий екран (`src/components/ErrorBoundary.tsx`). Заголовок вкладки — за розділом.
- **Прев'ю посилань** (Discord, Telegram, пошук): сервер вписує в сторінку назву, опис і картинку того, на що веде
  адреса — база зі знімком 3D, роадмап, білд, розрахунок, людина, гільдія (`server/lib/og.mjs`); лише те, що видно без
  входу. `public/robots.txt` закриває службове.
- **На головний екран** (`public/manifest.webmanifest`; значки `public/icons/` малює `node scripts/make-icons.mjs` з
  того ж знака, що й favicon): з ним на iPhone працюють нагадування про бурю.
- **Обмеження**: записів — до 600 за 5 хв на людину (без входу — 120 на адресу), нових позначок і записів ресурсів — 60
  за годину, листів із кодом — 20 на добу на пошту й 2000 на добу всього; великі тіла запитів (бази, вміст панелі) —
  лише з сеансом; живих потоків — до 20 на людину. Прибирання раз на годину чистить і протерміновані запрошення та
  заявки до гільдій, на які пів року ніхто не відповів.
- **Гільдії**: назва й тег — неповторні; запрошення за замовчуванням на один вхід, з вибором ролі (новобранець чи
  учасник); блокування людини передає лідерство наступному; службові логіни (`admin`, `support`, `sandwalkers`…)
  не взяти собі.
