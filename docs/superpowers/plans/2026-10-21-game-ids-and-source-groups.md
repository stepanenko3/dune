# Ігрові id для будівель, групи джерел, окремі сайти — план 4b

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** (1) сайт працює на ігрових id будівель — без таблиці відповідності «вікі ↔ гра» (видаляється разом з усім пов'язаним); (2) у «Дані гри» розділи, що мусять мати одне джерело, перемикаються групою, незалежні — окремо; (3) кожен сайт — окреме джерело (нема «questlog.gg + awakening.wiki»); (4) порівняння — поточне джерело з будь-яким іншим, повним списком із підсвіткою.

**Spec:** `docs/superpowers/specs/2026-10-21-game-data-drivers-design.md` — цей план змінює §6 (рішення користувача 2026-10-21): **таблиць відповідності нема й не буде**; публічні id — ігрові; старі збережені дані переводяться разовою міграцією, а не постійною таблицею.

## Рішення (погоджено 2026-10-21, з правками користувача)

Правки користувача: у сардаукарському наборі є не всі види елементів (форма без пари там — рядок іншого набору гри, де
вона є; перелік форм двигуна — як зараз, 134); **сторонні джерела прибираємо якомога більше вже зараз** — лишаються файли
гри й кілька названих винятків, а драйвери, групи й порівняння — переважно на майбутнє.

1. **Форми баз = ігрові рядки.** Двигун баз (`src/engine/pieces.js`) зараз називає форми id вікі (`foundation`, `wall`…), ціни — жорстка таблиця сардаукарського набору. Нові id форм — рядки гри набору `MTX_Sardaukar_BuildingSet_Patent` (`Sardaukar_Foundation`, `Sardaukar_Wall_01`… — 85 рядків, збіг з вікі-сардаукаром 83/85), форм, яких у сардаукарів нема, — рядок першого набору гри, де вона є. Ціни форм — з даних гри (ті самі `cost` рядка), а не з ручної таблиці.
2. **Пристрої баз = ігрові id пристроїв** (`SpiceRefinery_Placeable` замість `spice_refinery`); таблиці `POWER_OF`, `PLACE`, `RECIPE_BUILD` у `power.ts` (самі по собі відповідності) зникають — енергія й ціна беруться з пристрою за його id.
3. **Будівельні модулі — лише з файлів гри.** Збір модулів з awakening.wiki прибирається (його ключі несумісні з ігровими). Довідник будівель показує набори гри (лише випущене), назви наборів і модулів — з перекладів гри.
4. **Картинки будівель** — файл вікі з тим самим ім'ям, що текстура гри (`T_UI_IconPlayerPBSardFoundationR_D.png`; збіг 85/85 сардаукар, 626/948 усіх) — правило за іменем, не таблиця; розділ «Картинки» лишається на запасному джерелі.
5. **Разова міграція** (скрипт, запуск на `dune_preview`, потім на живій після `snotax db snapshot`): `bases.doc` і `base_history.doc` (`pieces[].shape`, `items[].type`), `bases.calc` (ключі `row:<shape>`, `extra[].id`), `calcs.doc.code` (`b~<set|id>~n` → `b~<рядок гри>~n`), `game_texts` (kind `buildable`), рядки `game_buildables` з ключами вікі → прибрані. Конверсія вшита лише в скрипт міграції й видаляється з коду після прогону на живій. Локальні збереження браузера (`calc:targets`, `base:<id>:calc`) з будівлями вікі — відкидаються з повідомленням «оновлено під дані гри».
6. **Сторонні джерела — геть, крім винятків.** Прибираються збори: questlog (довідник, уміння), awakening.wiki (стоси/рідкість предметів, будівельні модулі), gaming.tools (імпорт перекладів в адмінці), TH.GL (українські назви). Основне джерело кожного розділу — файли гри. **Винятки** (у серверних файлах нема пікселів чи даних ще не видобуто), кожен — окремий драйвер з однією назвою: `questlog` — іконки предметів і пристроїв (CDN) і, поки нема з гри, характеристики на картці предмета; `wiki` — картинки будівель за іменем текстури; `thgl` — тайли мапи й спрайт іконок (точки й розкладки — до плану 5); `redblink` — великі поля меланжу (до плану 5); gaming.tools у браузері — значення рангів атрибутів і спеціалізації умінь (поки їх нема в пакеті). Драйвер «запасне джерело» (community) зникає.
7. **Групи** (на майбутнє, коли в розділу буде кілька джерел; перемикаються разом, одне джерело на групу): **Довідник** = предмети + пристрої + рецепти (посилаються одне на одного); **Мапа** = мапи + точки + розкладки ГП + ресурси (точки в координатах мапи). Окремо: будівельні модулі (лише гра), уміння, переклади, поля меланжу, картинки, налаштування гри. Основне джерело — `primary:<група|розділ>`; міграція переносить нинішні `primary:items|placeables|recipes` у `primary:catalog` (якщо різні — бере items).

## Global Constraints

- Жива база `dune`: перед міграцією — `snotax db snapshot`; усі міграції в коді сервера — лише додаткові й ідемпотентні; DROP таблиці відповідності — окремим кроком міграції після знімка.
- Перевірка — на `dune_preview` (launch.json `gamedata-api`/`gamedata-web`), тестовому користувачу роль admin тимчасово.
- `npm run i18n:merge` без `--clean`. Тека не git. Невипущене ховається.
- Жодних таблиць відповідності в коді після міграції (перевіряється пошуком у фінальній рецензії).

## Review Focus

1. Збережена база (format 2) з живої після міграції відкривається в конструкторі з тими самими деталями, кошторис рахує ту саму кількість каменю/матеріалів.
2. Збережений розрахунок з будівлею (`calcs.doc.code`) після міграції відкривається з тим самим модулем.
3. Генератор баз і вітринні бази (`scripts/showcase`) будуються на нових id без помилок перевірки.
4. Перемикання групи «Довідник» не лишає рецепти на одному джерелі, а предмети на іншому.
5. Порівняння після перемикання показує справжню різницю (джерело читає свої останні дані, а не таблиці сайту).
