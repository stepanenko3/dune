# 3D-будівельник баз — дизайн

Дата: 2026-10-18. Проєкт: Sandwalkers (`dune`), сторінка бази та її редактор (`/bases/<id>/edit`).

## Навіщо

Зараз базу правлять на 2D-плані: приміщення з плиток, рівні, висоти, стіни — блоками в картці. Користувачу це
«дуже не зручно»: стіни, рівні й висоти доводиться тримати в голові, а результат видно лише в 3D поруч. У самій грі
будують інакше — деталь за деталлю просто в 3D. Хочемо так само: **будувати в 3D, як у грі**, а план, кошторис,
ліміти й рівні — **генерувати з того, що побудовано**.

Успіх: гравець гільдії відкриває редактор, вибирає зліва «Стіна», наводить на край фундаменту — бачить зелену примару,
клацає — стіна стоїть; праве клацання — прибрана. Повзунком зрізу заглядає всередину. План поверху й кошторис
оновлюються самі й точно рахують деталі.

## Цілі

- Повноцінний будівельник у 3D, як у грі: палітра деталей → примара з прив'язкою → клік ставить, правий клік прибирає.
- Будь-яка форма бази: різні висоти приміщень на одному поверсі, стіни поштучно (1×1 і 1×0,5), скісні стіни під дахами,
  дахи (скати, кути, трикутні), сходи, пандуси, колони, поручні.
- Деталь можна вибрати й **замінити** іншою того самого місця (стіна → двері, вікно, пентащит, напівстіна), повернути,
  віддзеркалити (ліва/права), прибрати.
- Повзунок **зрізу по висоті**: усе вище — сховано, щоб будувати всередині.
- **Приміщення** — простір, замкнений стінами, визначається сам; назву й призначення дають кліком по його підлозі.
- **Станції** (переробники, фабрикатори, сховища…) — ставляться з тієї ж палітри, як у грі.
- Генеруються: план кожного поверху (той самий вигляд, що зараз на сторінці бази), кошторис і ліміти — з деталей,
  точно; рівні (висоти підлог) — лише для показу зрізів і планів.
- Бази main і dd перетворюються на деталі автоматично (без ручної перебудови); видимо майже те саме.

## Не-цілі

- Набори й текстури гри (сардаукарський, атрідівський…): лише **базові форми**; вигляд — один, нейтральний (як зараз).
- Будування з телефона: на телефоні — лише перегляд (план, 3D, кошторис).
- Фізика й «стійкість» конструкцій гри. Перевіряємо лише, що деталь має опору й не налазить на іншу.
- Спільне редагування наживо кількома людьми (лишається як є: версії, конфлікт при збереженні).

## Анти-цілі (що зробило б це провалом, навіть якщо працює)

- Треба знову думати рівнями, висотами чи «блоками в картці», щоб поставити звичайну стіну.
- Примара не там, де очікуєш, чи клік ставить деталь не туди, куди наведено.
- Після перетворення main/dd база помітно інша або кошторис «з'їхав» без пояснення.
- 3D гальмує на великій базі (main — ~4 тисячі деталей) — fps не обмежуємо, роздільність на телефоні не нижче ×1,5
  (правило проєкту для 3D).

## Обмеження

- Стек проєкту: React + Vite + Tailwind + zustand; рушій — чистий JS у `src/engine/` (three.js r128 + OrbitControls,
  без збирання — `window.*` у браузері, `module.exports` у Node); сервер Express + SQLite.
- Бази — дані на сервері з версіями й історією (`server/lib/bases.mjs`, `cleanBase`); збереження — лише кнопкою
  «Зберегти»; чернетка — у браузері; «скасувати/повторити» з підписом дії.
- Сітка гри — як зараз: квадрат 1×1 і рівносторонній трикутник зі стороною 1 (координати плану x, y у плитках);
  висота — у блоках: стіна 1×1 заввишки 1 блок, напівстіна — 0,5.
- Ціни деталей — з довідника гри (`catalog.buildables`, набір за замовчуванням — сардаукарський): деталь-форма
  відповідає елементу набору з тим самим id (`wall`, `angled_roof_corner`…).
- Мова інтерфейсу — українська; коментарі в коді — українською, як у проєкті.

## Що вирішено з користувачем

- Редагування — у 3D; план і все інше генерується з 3D.
- Рівні лишаються **лише** для показу зрізу й автогенерації планів поверхів.
- Розкладка екрана — **варіант A**: палітра деталей зліва (категорії підписані, усе видно списком), 3D посередині на
  всю висоту, повзунок зрізу справа, згенерований план — маленьким вікном у кутку.
- Взаємодія: спершу вибір деталі (палітра); при наведенні — підсвічується, куди можна поставити; клік ставить, правий
  клік прибирає; вибрану деталь можна замінити; зріз — повзунком.
- Деталі — базові форми (трикутний дах, кут даху, скісні стіни, більші й менші варіанти), без наборів і текстур.
- Приміщення визначаються самі (замкнений стінами простір), назва — кліком по підлозі.
- main і dd — перетворити автоматично. Телефон — лише перегляд.

## Модель даних (документ бази, нова версія)

```
doc = {
  format: 2,
  pieces: Piece[],      // будова: фундаменти, стіни, дахи, сходи…
  items: Item[],        // станції й обладнання (як зараз items, але на рівні бази, з висотою z)
  zones: Zone[],        // назви приміщень: точка-«зерно» на підлозі + назва, призначення
  claims, ui, heights,  // як зараз
  levels,               // генеруються з висот підлог (лише для показу), як у floors.ts
}
Piece = { id, shape, x, y, z, rot, flip? }
  // shape — форма з бібліотеки (див. нижче); x, y — точка прив'язки на плані (центр плитки, середина краю чи вершина —
  // залежить від форми); z — висота низу деталі в блоках; rot — поворот (кратний 30°); flip — дзеркально (ліва/права)
Zone = { id, name, short?, group, note?, z, tiles: string[] }
  // приміщення = явні плитки (ключі центрів) на висоті z + саморозширення: незайнята нічиєю зоною підлога на тій самій
  // висоті, до якої можна дійти через краї без деталей; плитки, де підлоги вже нема, не рахуються
Item = { name, kind, c: {x,y}, z, w, d, h, ang, ...як зараз }
```

Стара модель (приміщення з плитками, `open`, `walls`) читається лише конвертером; сервер приймає обидві (поле
`format`), `cleanBase` знає `pieces`, `zones`, `items` і межі (не більше ~80 000 деталей).

## Бібліотека форм

Кожна форма описана один раз (`src/engine/pieces.js`): категорія, місце прив'язки (плитка, край, вершина), слід на
плані, розмір по висоті, геометрія для 3D, точки прив'язки («сокети»), що вона дає планові (лінія стіни, заливка
підлоги, символ сходів) і кошторису (який елемент гри, скільки ліміту). Форми — **усі різні форми з усіх наборів
гри, без текстур**: сардаукарські 85 і ті, яких у сардаукарському нема (люк, драбина, широкі сходи, стіна на 4,
широкі вікна…). Ціна — сардаукарська, а як форми в ньому нема — з набору, де вона є.

**Розміри форм** (підйом скатів і сходів, радіус заокруглених, висоти скісних і високих стін, розмір високих дверей і
воріт) у довіднику не дані — беремо за грою на око й тримаємо в одній таблиці бібліотеки. База зберігає лише форму
й прив'язку (не розміри), тож розміри можна підправити пізніше, не ламаючи збережених баз.

Категорії палітри:

- **Фундаменти**: квадрат, трикутник, заокруглений.
- **Перекриття** (підлога/стеля над стінами): квадрат, трикутник, заокруглені; «floor_2» тощо — подвійні.
- **Стіни** (на краї): стіна, напівстіна (0,5), широка на 2 і 3 плитки (ліва/права), заокруглена й пів-заокруглена.
- **Прорізи** (теж на краї, заміна стіни): вікно (ліве/праве), заокруглене вікно, двері (ліві/праві), високі двері,
  двері «Prudence», гаражні ворота, прохід, широкий прохід.
- **Пентащит** — як у грі, одна поверхня будь-якого розміру: складається з клітинок (вертикальні — на краю, 1×1 чи
  1×0,5; горизонтальні — на плитці), клітинки поспіль — одна поверхня. Ставиться рамкою (тягни). Кошторис — як зараз: один пентащит будь-якого розміру (матеріали раз, 2 будівельні елементи) і енергія —
  3 за кожну секцію 1×1.
- **Скісні стіни** (під скатами даху): трикутна стіна низ/верх, ліва/права, повна й половинна, висока.
- **Дахи**: пласкі (rooftop, трикутний, заокруглені), скати на 1, 2 і 3 плитки (лівий/правий), зовнішній і
  внутрішній кут, трикутний скат низ/верх, заокруглений.
- **Сходи й пандуси**: сходи, кут, внутрішній кут, пів-сходи; пандус і його кути; високі пандуси.
- **Колони й поручні**: колона (низ/середина/верх), кутова й центральна колона; поручень, хвіртка, заокруглений,
  похилий поручень.
- **Станції**: з довідника пристроїв (як зараз «Станції» в редакторі), з пошуком.

Іконки палітри — картинки цих елементів з вікі (вони вже є в довіднику, `buildables[].img`).

## Будування (взаємодія)

- **Палітра зліва** (варіант A): категорії, у кожній — деталі іконками з назвами; пошук; останні вжиті згори.
  Клавіші: 1–9 — деталі поточної категорії, R — поворот, F — віддзеркалити (ліва/права), Esc — без деталі,
  Del — прибрати вибране, Ctrl+Z / Ctrl+Shift+Z.
- **Примара**: вибрана деталь біля курсора чіпляється до найближчого підхожого сокета, як у грі: фундамент — до
  краю іншого фундаменту чи на землю в сітці; стіна — на край фундаменту, перекриття чи на верх іншої стіни; перекриття —
  на верх стін чи до краю іншого перекриття; дах — на верх стін; скісна стіна — під скат; сходи — на підлогу.
  Зелена — можна; червона — налазить чи нема опори (з підказкою, чому). Колесо миші чи R — поворот між дозволеними.
- **Клік** — поставити; можна тягнути, щоб ставити рядом (стіни вздовж краю, фундаменти рамкою) — як «рамка» зараз.
- **Правий клік** по деталі — прибрати (з підсвіткою, що саме зникне).
- **Без вибраної деталі** клік вибирає деталь: картка поруч — «Замінити на…» (лише форми, що стають у те саме місце:
  стіна → двері, вікно, пентащит, напівстіна, прохід…), поворот, дзеркально, «Прибрати». Shift — кілька.
- **Зріз**: вертикальний повзунок справа, крок — пів блоку; ховає все, що вище; на зрізі видно підлоги, стіни
  обрізані. Примара працює лише на видимому.
- **Камера**: як зараз (OrbitControls): обертання, наближення; подвійний клік — центрувати на деталі.
- **План у кутку**: поточний поверх (за зрізом), клік — перейти до місця в 3D.

## Приміщення

- Приміщення не малюють: це зв'язна підлога (фундаменти чи перекриття на одній висоті), замкнена деталями на краях —
  **будь-якими, і проходами й дверима теж** (як у грі: прохід — це деталь стіни); з'єднує лише край, де деталі нема.
  Так приміщення main (заїзд і гаражі, зал і крила) лишаються окремими. Висота — до стелі над підлогою.
- Два зерна в одному просторі — назва першого; редактор підсвічує конфлікт.
- Інструмент/режим «Приміщення»: клік по підлозі — картка: назва, коротка назва, призначення (колір на плані), нотатка.
  Нова зона — заповнення від клацнутої плитки до стін; зберігається як `Zone` з явними плитками; нова підлога в тому
  самому замкненому просторі додається сама (ділити зону — прибрати й назвати наново).
- Неназвані замкнені простори на плані — без підпису (чи «Приміщення» сірим).

## Станції

Як зараз (розмір, поворот, «за стіну не стане», «налазить на іншу» — жовтим), але ставляться в 3D на підлогу під
курсором; належність до приміщення — за місцем.

## Що генерується

- **Рівні**: висоти підлог (фундаменти й перекриття), як у `floors.ts`; лише кнопки зрізу/плану.
- **План поверху** (сторінка бази й кут редактора): підлоги поверху, стіни й прорізи на висоті поверху, приміщення з
  назвами, станції, сходи; притемнене тло з інших поверхів — як зараз.
- **3D сторінки бази**: з деталей (той самий рендер, що в редакторі).
- **Кошторис і ліміти**: кількість кожної форми → елементи гри й ціни довідника (двері — одна деталь за ціною
  довідника, 17 каменю); кожна деталь — 1 будівельний елемент, хоч якого розміру; двері ще й у ліміт «Двері», як
  зараз; пентащити — як вище; «Калькулятор бази» отримує цілі з деталей.
- **План будівництва по етапах** (картка на сторінці бази): етапи — за рівнями, знизу вгору (фундамент, далі для
  кожної висоти підлоги — перекриття, стіни, дахи); підписи й поради етапів (`ui.stages`, `ui.howto`) — за ключем
  рівня.

## Перехід main і dd

- Конвертер старої моделі в деталі: плитки приміщень → фундаменти (на землі) чи перекриття; периметр × висота →
  стіни поштучно (з `walls` і `open`: двері, пентащит, прохід, напівстіни); дахи → пласкі дахи, яруси піраміди, корони,
  обідки, скати — найближчими формами; заокруглені профілі заїздів → пандуси; станції → `items`; назви приміщень →
  `zones` (зерно — центр підлоги).
- Коли стара форма не складається з деталей гри, **перемагають деталі гри**: двері — деталь дверей (високі, якщо
  проріз ≥ 2 блоків) і стіна чи напівстіна над нею; висоти — до 0,5 блоку; верхівка піраміди, ліхтарі веж, скоси
  карнизів — найближчими формами. Усі такі відмінності — переліком у примітці до версії.
- **Етап 1** — перетворення лише для показу (у браузері, при відкритті), щоб порівняти й поправити конвертер; гільдія
  тим часом править як звичайно. **Етап 2** — одне збереження новою версією з приміткою (стара лишається в історії
  й відновлюється), і з цього моменту база — у деталях.
- Перевірка: 3D «на око» той самий; кошторис — різниця пояснена (новий рахує точно за формами).

## Етапи

1. **Деталі й перегляд**: бібліотека форм, рендер деталей у 3D, генерація плану й кошторису з деталей, конвертер;
   сторінка бази показує main і dd із деталей. Старий редактор ще працює на старій моделі (для порівняння).
2. **3D-будівельник**: палітра, примара з сокетами, поставити/прибрати, вибрати/замінити, зріз, «скасувати», чернетка,
   збереження.
3. **Приміщення й станції в 3D**.
4. Прибрати старий 2D-редактор і стару модель (крім конвертера).

## Залишено будівельнику

Математика сокетів і прив'язки; як рендерити багато деталей (інстансинг тощо); структура файлів рушія; формат
`rot`/`flip` у деталях; як саме конвертувати складні дахи main (найближчими формами); тести.

## Мої рішення (не обговорювались — перевір)

- Форми — усі різні з усіх наборів (без текстур); ціни — сардаукарські, інакше — з набору, де форма є.
- Розміри форм — за грою на око, в одній таблиці; бази зберігають лише форму й прив'язку.
- Пентащит — одна поверхня будь-якого розміру (вертикальна й горизонтальна), рамкою; кошторис — як зараз.
- Приміщення обмежує будь-яка деталь на краю, і прохід теж; з'єднує лише порожній край.
- При перетворенні main і dd перемагають деталі гри (двері стають дверима гри, над ними — стіна), відмінності — у
  примітці до версії.
- Етап 1 — перетворення лише для показу; збережене перетворення — на етапі 2.
- Етапи «Плану будівництва» — за рівнями; кожна деталь — 1 будівельний елемент; двері — одна деталь (17 каменю).
